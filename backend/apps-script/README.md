# ตั้งค่าเซิร์ฟเวอร์เกม (Google Sheet + Apps Script)

เซิร์ฟเวอร์ของ Survivor Isles (ชื่อเดิม LAST PIXEL) คือ Google Sheet หนึ่งไฟล์ที่มีโค้ด Apps Script ติดอยู่ ชีตนี้เก็บบัญชีผู้เล่น เซฟเกม แผนที่โลก ตลาด และตารางอันดับ ทำให้เล่นต่อจากเครื่องไหนก็ได้ บัญชีใช้ **อีเมล + รหัสผ่าน** และยืนยันอีเมลด้วยรหัส 6 หลักที่เซิร์ฟเวอร์ส่งผ่าน Gmail ของเจ้าของชีต (MailApp)

ใช้บัญชี Google ธรรมดาได้ ไม่เสียเงิน ทำครั้งเดียวประมาณ 10 นาที

> ไฟล์ในโฟลเดอร์นี้
> - `Code.gs` โค้ดเซิร์ฟเวอร์ทั้งหมด
> - `appsscript.json` การตั้งค่าโปรเจกต์ (เขตเวลาไทย การเปิดเป็นเว็บแอป และสิทธิ์ที่ใช้: แก้ชีต + ส่งอีเมล)

---

## ⚡ อัปเดตเซิร์ฟเวอร์ที่ใช้อยู่แล้วเป็นระบบอีเมล (ทำครั้งเดียว ~5 นาที)

ข้อมูลเดิมไม่หาย บัญชีเดิมยังเข้าได้ URL เดิมไม่เปลี่ยน

1. เปิดชีต `LastPixel-DB` → **ส่วนขยาย → Apps Script**
2. คลิก `Code.gs` → ลบโค้ดเดิมทั้งหมด → วาง `backend/apps-script/Code.gs` ใหม่ทั้งไฟล์ → 💾 บันทึก
3. คลิก `appsscript.json` → ลบทั้งหมด → วาง `backend/apps-script/appsscript.json` ใหม่ → 💾 บันทึก
   (ไม่เห็นไฟล์นี้: ⚙ **การตั้งค่าโปรเจกต์** → ติ๊ก **แสดงไฟล์ Manifest "appsscript.json" ในเครื่องมือแก้ไข**)
4. ช่องเลือกฟังก์ชันด้านบน เลือก **`setup`** → ▶ **เรียกใช้**
   - Google จะ **ขอสิทธิ์ใหม่** (เพิ่ม "ส่งอีเมลในนามคุณ") → **ตรวจสอบสิทธิ์** → เลือกบัญชี → **ขั้นสูง** → **ไปที่ … (ไม่ปลอดภัย)** → **อนุญาต**
   - รอบันทึกการดำเนินการขึ้น `ชีต Accounts: เพิ่มคอลัมน์ email, verified, verifyHash, verifyExp, verifyTries (ข้อมูลเดิมอยู่ครบ)` และ `setup เสร็จ …`
5. **ทำให้ใช้งานได้ → จัดการการทำให้ใช้งานได้** → ✏ ที่รายการเดิม → **เวอร์ชัน: เวอร์ชันใหม่** → **ทำให้ใช้งานได้** (ถ้าขอสิทธิ์อีกให้กดอนุญาต)
6. ทดสอบ: เปิดเกม → **สมัครสมาชิก** ด้วยอีเมลจริง → ต้องได้อีเมลหัวเรื่อง `Survivor Isles — รหัสยืนยันอีเมล ……` (ดูในสแปมด้วย)

**บัญชีเดิม (ก่อนมีอีเมล เช่น `Tawan`)** พิมพ์ชื่อผู้ใช้เดิมในช่อง "อีเมล" + รหัสผ่านเดิม → เกมให้ **ผูกอีเมล** (ส่งรหัสไปที่อีเมลนั้น → ใส่รหัส) → ครั้งต่อไปเข้าด้วยอีเมลเท่านั้น · กด "ไว้ทีหลัง" ได้ (ยังเข้าด้วยชื่อผู้ใช้ได้จนกว่าจะผูก)

> ขั้น 3 ไม่บังคับ (ถ้าข้าม Google ตรวจจากโค้ดเองว่าต้องใช้สิทธิ์ส่งอีเมล) แต่แนะนำให้ทำ ให้ตรงกับไฟล์ในโปรเจกต์ · **ห้ามข้ามขั้น 4 และ 5** — ไม่รัน `setup` = ยังไม่ได้สิทธิ์ส่งอีเมล (สมัครแล้วไม่มีรหัสส่งไป) · ไม่ deploy เวอร์ชันใหม่ = URL ยังใช้โค้ดเก่า

## ขั้นที่ 1: สร้าง Google Sheet

1. เปิด https://sheets.google.com แล้วกด **ว่าง** (Blank) เพื่อสร้างสเปรดชีตใหม่
2. ตั้งชื่อไฟล์ตรงมุมซ้ายบน เช่น `LAST PIXEL Server`

## ขั้นที่ 2: วางโค้ด

1. ที่เมนูด้านบนของชีต กด **ส่วนขยาย** → **Apps Script** (ภาษาอังกฤษคือ Extensions → Apps Script) จะมีแท็บใหม่เปิดขึ้นมา
2. ฝั่งซ้ายจะเห็นไฟล์ `Code.gs` ให้คลิกไฟล์นี้ แล้ว **ลบโค้ดเดิมออกให้หมด** (`function myFunction() {...}`)
3. เปิดไฟล์ `backend/apps-script/Code.gs` ในโปรเจกต์นี้ คัดลอกทั้งหมดแล้ววางลงไป
4. กดไอคอน 💾 **บันทึกโปรเจกต์** (หรือ Ctrl+S / Cmd+S)
5. (แนะนำ) ตั้งค่า manifest
   - กด ⚙ **การตั้งค่าโปรเจกต์** (Project Settings) ที่แถบซ้าย
   - ติ๊ก **แสดงไฟล์ Manifest "appsscript.json" ในเครื่องมือแก้ไข**
   - กลับไปที่ **เครื่องมือแก้ไข** (ไอคอน `< >`) จะมีไฟล์ `appsscript.json` เพิ่มมา ให้แทนที่เนื้อหาด้วยไฟล์ `backend/apps-script/appsscript.json` แล้วบันทึก

## ขั้นที่ 3: รัน `setup` ครั้งเดียว

1. ที่แถบด้านบนของเครื่องมือแก้ไข มีช่องเลือกฟังก์ชัน ให้เลือก **`setup`**
2. กด ▶ **เรียกใช้** (Run)
3. ครั้งแรกจะมีหน้าต่างขอสิทธิ์
   - กด **ตรวจสอบสิทธิ์** (Review permissions) แล้วเลือกบัญชี Google ของคุณ
   - ถ้าขึ้นว่า "Google ไม่ได้ยืนยันแอปนี้" ให้กด **ขั้นสูง** (Advanced) → **ไปที่ LAST PIXEL Server (ไม่ปลอดภัย)** ข้อความนี้ขึ้นเพราะเป็นโค้ดที่เราเขียนเอง ไม่ใช่แอปจาก Google
   - กด **อนุญาต** (Allow)
   - หน้าขอสิทธิ์จะมี 2 ข้อ: ดู/แก้สเปรดชีต และ **ส่งอีเมลในนามคุณ** (ใช้ส่งรหัสยืนยัน 6 หลักให้ผู้เล่น)
4. รอจน **บันทึกการดำเนินการ** (Execution log) ด้านล่างขึ้นว่า `setup เสร็จ · seed โลก = ...`
5. กลับไปดูที่ชีต จะมีแท็บใหม่ 9 แท็บ: `Accounts` `Sessions` `Saves` `Meta` `World` `Market` `Leaderboard` `Log` `Config`

## ขั้นที่ 4: เปิดเป็นเว็บแอป (Deploy)

1. ที่มุมขวาบนของ Apps Script กด **ทำให้ใช้งานได้** → **การทำให้ใช้งานได้รายการใหม่** (Deploy → New deployment)
2. กดไอคอน ⚙ ข้างคำว่า **เลือกประเภท** (Select type) แล้วเลือก **เว็บแอป** (Web app)
3. กรอกตามนี้
   - **คำอธิบาย**: อะไรก็ได้ เช่น `v1`
   - **ดำเนินการในฐานะ** (Execute as): **ฉัน** (Me — อีเมลของคุณ)
   - **ผู้ที่มีสิทธิ์เข้าถึง** (Who has access): **ทุกคน** (Anyone) ← ต้องเลือกอันนี้ ไม่งั้นเกมเรียกไม่ได้
4. กด **ทำให้ใช้งานได้** (Deploy) ถ้าขอสิทธิ์อีกครั้งให้กดอนุญาตเหมือนขั้นที่ 3
5. จะได้ **URL ของเว็บแอป** หน้าตาแบบ `https://script.google.com/macros/s/AKfy.../exec` ให้กด **คัดลอก**

ทดสอบ: เอา URL ไปเปิดในเบราว์เซอร์ ถ้าเห็น `{"ok":true,"name":"last-pixel",...}` แปลว่าใช้ได้ (`last-pixel` เป็นชื่อภายในของโปรโตคอล คงไว้ตามเดิม)

## ขั้นที่ 5: บอกเกมให้ใช้เซิร์ฟเวอร์นี้

**เว็บจริงบน GitHub Pages**
1. เปิด repo บน GitHub → **Settings** → **Secrets and variables** → **Actions**
2. เลือกแท็บ **Variables** → กด **New repository variable**
3. Name: `API_URL` · Value: วาง URL จากขั้นที่ 4 → **Add variable**
4. ไปที่แท็บ **Actions** → เลือก workflow **Deploy to GitHub Pages** → **Run workflow** (หรือ push โค้ดใหม่) เพื่อ build ใหม่ เกมจะเริ่มใช้เซิร์ฟเวอร์

**รันในเครื่อง**
1. คัดลอกไฟล์ `.env.local.example` เป็น `.env.local` ที่โฟลเดอร์หลักของโปรเจกต์
2. ใส่บรรทัด `NEXT_PUBLIC_API_URL=https://script.google.com/macros/s/AKfy.../exec`
3. ปิดแล้วเปิด `npm run dev` ใหม่

ถ้าเกมต่อเซิร์ฟเวอร์ได้ มุมซ้ายล่างของหน้าแรกจะขึ้น **🟢 ออนไลน์**

## แก้โค้ดแล้วต้องทำอะไร

ทุกครั้งที่แก้ `Code.gs` ต้อง deploy เวอร์ชันใหม่ ไม่งั้น URL เดิมยังใช้โค้ดเก่า

1. วางโค้ดใหม่แล้วบันทึก (ถ้า `appsscript.json` เปลี่ยนด้วย ให้วางแล้วรัน `setup` หนึ่งครั้งเพื่อกดอนุญาตสิทธิ์ใหม่ · ถ้า `HEADERS` ใน Code.gs เพิ่มคอลัมน์ ก็รัน `setup` เช่นกัน)
2. **ทำให้ใช้งานได้** → **จัดการการทำให้ใช้งานได้** (Manage deployments)
3. กดไอคอน ✏ (แก้ไข) ที่รายการเดิม → ช่อง **เวอร์ชัน** เลือก **เวอร์ชันใหม่** (New version) → **ทำให้ใช้งานได้**

วิธีนี้ URL ยังเป็นอันเดิม ไม่ต้องแก้ `API_URL`

## งานดูแล (สำหรับแอดมิน)

| อยากทำ | วิธี |
|---|---|
| แบนผู้เล่น | ชีต `Accounts` ช่อง `banned` ของคนนั้นพิมพ์ `TRUE` (มีผลภายใน 10 นาที) |
| ผู้เล่นไม่ได้รับอีเมลรหัส | ให้ดูโฟลเดอร์สแปมก่อน · ยืนยันให้เองได้: ชีต `Accounts` ช่อง `verified` พิมพ์ `TRUE` แล้วให้เขาเข้าสู่ระบบใหม่ · ดูชีต `Log` หา `mail.fail` (โควตาเต็ม/ส่งไม่ได้) |
| เปลี่ยนอีเมลของบัญชี | แก้ช่อง `email` (ตัวพิมพ์เล็ก ห้ามซ้ำกับบัญชีอื่น) · ช่องว่าง = กลับเป็นบัญชีแบบเก่าที่เข้าด้วยชื่อผู้ใช้แล้วให้ผูกอีเมลใหม่ |
| บัญชีสมัครค้างไม่ยืนยัน | ไม่ต้องทำอะไร — เกิน 1 วันแล้วมีคนสมัครด้วยอีเมล/ชื่อเดียวกัน ระบบลบแถวค้างให้เอง (ลบแถวเองก็ได้ถ้า `verified` ไม่ใช่ `TRUE`) |
| ลบเกาะคนที่เลิกเล่น | ลบแถวของคนนั้นในชีต `World` (ช่องเกาะจะว่างให้คนใหม่) |
| รีเซ็ตโลกใหม่ทั้งหมด | ลบแถว `worldSeed` ในชีต `Config` + ลบแถวข้อมูลใน `World` `Saves` แล้วรัน `setup` อีกครั้ง (เซฟเดิมจะใช้ไม่ได้ เพราะเกาะถูกสร้างจาก seed) |
| ดูว่าเกิดอะไรขึ้น | ชีต `Log` (สมัคร ยืนยันอีเมล เข้าระบบ ใส่รหัสผิด ลืมรหัสผ่าน ผูกอีเมล ส่งอีเมลไม่สำเร็จ เข้าโลก ซื้อของ error) เก็บล่าสุดประมาณ 3,000 แถว |

**ห้ามแก้หัวตาราง (แถวแรก) หรือสลับลำดับคอลัมน์** โค้ดอ่านข้อมูลตามตำแหน่งคอลัมน์ (คอลัมน์ใหม่ต่อท้ายเสมอ `setup` เติมหัวตารางที่ขาดให้เอง)

## ข้อมูลทางเทคนิค

- **รูปแบบคำขอ**: `POST` ไปที่ URL เว็บแอป body เป็น JSON ส่งแบบ `Content-Type: text/plain;charset=utf-8` (เบราว์เซอร์จะไม่ยิง CORS preflight ซึ่ง Apps Script ตอบไม่ได้) เช่น `{"action":"save.get","token":"t..."}`
- **คำตอบ**: `{ "ok": true, ... }` หรือ `{ "ok": false, "error": "ข้อความภาษาไทย", "code": "auth" }`
- **action**: `ping` · บัญชี `register` `verify` `resend` `login` `forgot` `reset` `email.attach` `email.confirm` `logout` `me` · `save.get` `save.put` `save.clear` · `meta.get` `meta.put` · `world.get` `world.join` `world.leave` `world.heartbeat` · `market.list` `market.post` `market.buy` `market.cancel` `market.claim` · `leaderboard.get` `leaderboard.submit` (ทุกอันยกเว้น `ping` `register` `verify` `resend` `login` `forgot` `reset` ต้องมี `token`)
- **code ที่ใช้บ่อย**: `auth` (token หมดอายุ) · `stale` (มีเซฟใหม่กว่าจากเครื่องอื่น) · `rate` (ลองรหัสผิด/ขอรหัสบ่อยเกิน) · `invalid` · `taken` (ชื่อในเกมซ้ำ) · `email_taken` · `bad_login` · `unverified` · `use_email` · `bad_code` · `expired` · `too_many` · `cooldown` (+ `wait` วินาที) · `mail` · `mail_quota` · `has_email` · `sold` · `full` · `busy` · `too_large`

**บัญชีและอีเมล**

| action | ส่ง | ได้ |
|---|---|---|
| `register` | email, password, name (ชื่อในเกม) | `{ needVerify: true, email, sent, wait, message }` — **ยังไม่มี token** ส่งรหัส 6 หลักไปที่อีเมล |
| `verify` | email, code | token, expiresAt, account (เหมือน login) |
| `resend` | email | `{ wait, message }` (ข้อความเดียวกันทุกกรณี) · `cooldown` ถ้ายังไม่พ้น 60 วิ |
| `login` | email (หรือ `username` ของบัญชีเก่า), password | token, expiresAt, account · ยังไม่ยืนยัน → `code: 'unverified'` + email, sent, wait (ส่งรหัสใหม่ให้เองถ้าพ้น 60 วิ) |
| `forgot` | email | `{ wait, message: 'ถ้ามีบัญชีนี้ เราได้ส่งรหัสไปแล้ว' }` เสมอ (ไม่บอกว่ามีบัญชีไหม) |
| `reset` | email, code, password | token ใหม่ · ยืนยันอีเมลให้ด้วย · token เดิมทุกเครื่องใช้ไม่ได้ |
| `email.attach` 🔑 | email | ส่งรหัสไปที่อีเมลนั้น (บัญชีเก่าที่ยังไม่มีอีเมลเท่านั้น) |
| `email.confirm` 🔑 | code | account (มี email แล้ว) — ต่อไปต้องเข้าด้วยอีเมล |

`account` = `{ id, username (ชื่อในเกม/ชื่อผู้ใช้เดิม), createdAt, email, needEmail }` · 🔑 = ต้องมี token

- **กติกา**: อีเมลเก็บตัวพิมพ์เล็ก ห้ามซ้ำ · รหัสผ่านใหม่ 8–64 ตัว มีตัวอักษรและตัวเลข (บัญชีเก่ารหัส 6 ตัวยังเข้าได้) · ชื่อในเกม 3–16 ตัว ไทย/อังกฤษ/ตัวเลข/_ ห้ามซ้ำ (เทียบกับชื่อผู้ใช้เดิมด้วย)
- **รหัสยืนยัน**: 6 หลัก อายุ 15 นาที ใส่ผิดได้ 5 ครั้ง (ครบแล้วต้องขอใหม่) ขอใหม่ได้ทุก 60 วิต่ออีเมลต่อประเภท ≤ 6 ฉบับ/ชั่วโมง/อีเมล ≤ 40 ฉบับ/10 นาทีทั้งระบบ · ชีตเก็บแค่ `<ประเภท>$<อีเมล>$<SHA-256>` ในช่อง `verifyHash` ไม่เก็บตัวรหัส
- **โควตาอีเมล**: Gmail ธรรมดาส่งผ่าน MailApp ได้ประมาณ **100 ฉบับ/วัน** (Workspace ~1,500) หมดแล้วเกมขึ้น "วันนี้ส่งอีเมลครบโควตาแล้ว" (`mail_quota`) จนถึงรอบรีเซ็ตของ Google · บัญชีที่สมัครแล้วแต่ส่งอีเมลไม่สำเร็จ ให้กด "ส่งรหัสอีกครั้ง" ภายหลัง หรือแอดมินพิมพ์ `TRUE` ในช่อง `verified`
- **รหัสผ่าน**: ไม่เก็บตัวจริง เก็บ salt สุ่ม + SHA-256 วนซ้ำ 2,000 รอบ (`CFG.HASH_ITER` ใช้เวลาประมาณ 0.2–0.5 วินาทีต่อการเข้าระบบ เพราะ Apps Script ช้า) ในรูป `v1$<รอบ>$<hex>` ถ้าเปลี่ยนจำนวนรอบ บัญชีเก่ายังเข้าได้
- **token**: สุ่ม 256 บิต อายุ 30 วัน ชีต `Sessions` เก็บแค่แฮช SHA-256 ของ token (คนเปิดชีตเห็นก็เอาไปใช้ไม่ได้)
- **เซฟ**: บีบอัดด้วย gzip + base64 แล้วแบ่งช่องละ ≤ 45,000 ตัวอักษร (ช่องของชีตรับได้ 50,000) ลงคอลัมน์ `data_1`, `data_2`, … ของชีต `Saves` เซฟหลังบีบอัดยาวได้สูงสุด 2 ล้านตัวอักษร
- **ล็อก**: งานที่ชนกันได้ (สมัคร รับช่องเกาะ ซื้อขาย สร้างแถวใหม่) ใช้ `LockService` ทีละคำขอ เช่น สองคนกดซื้อของชิ้นเดียวกัน จะได้แค่คนเดียว
- **ทดสอบในเครื่อง**: `npm run test:api` จะรัน `Code.gs` ตัวนี้ใน Node (จำลองชีตและ MailApp ในหน่วยความจำ) แล้วทดสอบทุก action รวมสมัคร→ยืนยัน, รหัสผิด/หมดอายุ, รอส่งใหม่, ลืมรหัสผ่าน, บัญชีเก่า→ผูกอีเมล และการเติมคอลัมน์ตอน `setup` · `npm run mock-api` พิมพ์หัวเรื่องอีเมล (มีรหัส) ลง console · action `__mail` `__clock` `__legacy` มีเฉพาะใน mock ไม่มีใน Code.gs
